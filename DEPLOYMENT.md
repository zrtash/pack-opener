# Публикация FootPacks на бесплатном Firebase Spark

Сайт публикуется через GitHub Pages. Firebase Authentication и Firestore сохраняют аккаунты и прогресс. Игровые действия пока выполняются в браузере, а готовое состояние сохраняется напрямую в Firestore.

## Что защищено и что пока нельзя гарантировать

- Firestore разрешает игроку читать и менять только собственный документ `users/{uid}`. Изменять общую базу `players` может только аккаунт с серверным custom claim `admin: true`.
- Правила проверяют форму и размеры сохранений, позиции состава, список известных наград и поля новых общих карточек, ограничивают лишние поля и сверяют лидерборд с облачным профилем. Это уменьшает риск повреждённых данных и случайных ошибок.
- Эти правила не могут доказать, что игрок честно открыл пак или заработал монеты: браузер игрока контролирует игровую логику и может записать поддельные значения в его собственный профиль. Чужие профили и общую базу карточек правила закрывают.
- Защита формы поддержки сочетает лимит Firestore — одно сообщение в минуту на аккаунт — с привязкой лимита к ID сообщения, honeypot и минимальной задержкой отправки. Правило блокирует отправку нескольких сообщений одним пакетом. Это не заменяет серверную CAPTCHA и может обходиться через другие аккаунты.
- Внешняя Яндекс.Метрика, карта кликов и запись сессий удалены из страницы. Для звуков используются короткие синтезированные сигналы браузера; внешние аудиофайлы не загружаются.
- Cloud Functions в текущей бесплатной версии не используются. Их код в `functions/` не вызывается сайтом. Публиковать функции не нужно; Firebase ранее потребовал для этого план Blaze.
- App Check для серверных функций не включён: без зарегистрированного ключа приложения он может блокировать легитимные запросы. Перед будущим подключением функций нужно зарегистрировать сайт в Firebase App Check и включить проверку после настройки клиента.
- Веб-версия не выполняет вход через Telegram Mini App. В исходнике будущего Telegram endpoint убран пароль, который вычислялся из Telegram ID; старые Telegram-профили с таким способом входа требуют отдельной безопасной привязки.

## Публикация бесплатной версии

1. Открой терминал именно в корне проекта `FootballersCard` и войди в Firebase, если ещё не вошёл:

   ```powershell
   firebase login
   ```

2. Опубликуй только Firestore Rules. Это не развёртывает Cloud Functions. Через CLI команда такая:

   ```powershell
   firebase deploy --only firestore:rules
   ```

   Если CLI не настроен, открой Firebase Console → **Databases & Storage → Firestore → Rules**, замени весь текст редактора полным содержимым файла `firestore.rules` и нажми **Publish**. Вставляй файл целиком, начиная с `rules_version = '2';`, а не отдельную строку `allow`. После публикации храни ту же версию в локальном файле: следующий CLI deploy заменит правила из консоли содержимым этого файла.

3. В GitHub замени `index.html`, `style.css` и `script.js` версиями из проекта и добавь из корня проекта файлы `pep-guardiola.jpg` и `favicon.png`. Они нужны для портрета тренера и облегчённой иконки сайта. Существующие `CNAME` и `logo.png` оставь на месте, чтобы сохранить домен и исходный логотип. Файл `firestore.rules` можно хранить в GitHub как резервную копию, но GitHub Pages его не публикует — правила устанавливаются способом из шага 2.

4. Дождись обновления GitHub Pages, затем перезагрузи страницу с `Ctrl+F5` и проверь вход, открытие паков, продажу последней карточки, состав, ИПК, коллекционные награды, поддержку и админку.

Существующие документы `users/{uid}` и рекорды не удаляются. Клиент нормализует старые поля перед следующим сохранением; никакого сброса прогресса при публикации не требуется.

## Каталог для будущего серверного режима

Сайт содержит 80 встроенных карточек. Если позже будет подключаться серверная игровая логика, перед изменениями каталога обновляй серверный JSON:

```powershell
npm run sync-game-data --prefix functions
```

Это обновляет `functions/game-data.json`. Сейчас файл нужен только будущему серверному режиму; его публикация не меняет работающий сайт на Spark.

## Поддержка

Обращения сохраняются в Firestore в коллекцию `supportMessages`; прочитать их можно в Firebase Console. Правила ограничивают сообщение 1200 символами, разрешают отправку только вошедшему игроку, применяют минутный интервал и связывают документ обращения с единственным ID в rate-limit документе. Это блокирует пачку обращений одной атомарной записью. Honeypot в интерфейсе — лишь дополнительный фильтр, его нельзя считать серверной защитой от ботов.

## Администратор

Скрытие админских кнопок само по себе не является защитой. Право на изменение общей базы карточек проверяется Firestore Rules по custom claim `admin: true`. Начисление монет и выдача коллекции пока изменяют сохранение текущего аккаунта через браузер. Это не позволяет одному игроку записать данные в чужой UID, но игрок способен подделать собственный баланс через инструменты браузера.

Для неподделываемой экономики понадобится доверенный сервер, который проверяет каждое игровое действие. Текущая бесплатная схема Firebase такой проверки не предоставляет.
